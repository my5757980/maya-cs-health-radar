2
Why it stays unsolved

Three failures compound.

Signals are fragmented

Evidence sits in the support inbox, product analytics, the CRM and billing. Assembling one account's picture by hand takes ~20 minutes.

Detection is calendar-driven

Risk is discovered when a renewal date approaches. A problem with a five-month runway gets a 30-day response window.

Knowing is not acting

A credible, context-specific outreach takes 15–25 minutes to write. At 6pm the at-risk account gets a generic check-in — or nothing.

3
The target user

One person. Named, not generic.

An individual-contributor CSM at a growth-stage B2B SaaS company — 30–150 employees, $3M–$20M ARR. Accounts are $8k–$60k ACV: too small for a named account team, too large to ignore. She reports on Net Revenue Retention and is paid partly on renewals, so churn is personally expensive. She is fluent in SaaS tools, but will not write SQL and will not configure a rules engine.

Not for: enterprise CSMs with named account teams · support agents · VP-level portfolio reporting · PLG companies with no CSM function.

5
The decision worth explaining

The score is code. Never a model.

// pure, synchronous, no network call, no AI
penalty(signal) = base_weight[type] × severity_mult[severity] × decay(ageDays)
decay(ageDays)  = max(0, 1 − ageDays / 90)
score          = clamp(round(100 − Σ penalty), 0, 100)
tier          = ≥70 healthy · ≥40 watch · else critical

The same signals always produce the same score — so cause and effect can be verified live rather than taken on trust. Every account page shows the full per-signal breakdown behind its number.

7
Where the model earns its place

Grounding is enforced in code
and schema — not in the prompt.

  • Every explanation must cite ≥ 2 real signals — a Postgres CHECK constraint makes an ungrounded recommendation impossible to save.
  • Returned citation ids are validated server-side as a subset of the context actually supplied. An invented citation is rejected outright, not filtered out.
  • Actions are bounded to a six-value Postgres enum. Out-of-taxonomy output retries once, then falls back to the driver default at low confidence.
  • signals grants SELECT and INSERT only. Evidence is immutable — which is what makes the audit timeline trustworthy.
8
The human boundary

Nothing is ever sent.

Approving records the decision and the final message text. It does not transmit anything.

There is no email client, no SMTP configuration and no outbound sender anywhere in the codebase — the guarantee is enforced by absence, not by a flag that could be flipped. The UI says so plainly, on every draft.

This is what makes it deployable in a real CS organisation on day one: the agent never touches a customer without a person signing off.

9
How it was built

native.builder, end to end.

Product Architect

Planned the project from a written brief — four screens, seven entities, a six-step workflow — and interrogated it with clarifying questions before any code was generated.

Builder agent

Generated the React front end, the full Postgres schema with row-level security, the seed dataset, and three Supabase Edge Functions calling Claude.

QA agent

Independently verified the build and caught two real defects — including a broken demo-user auth path silently returning zero rows through RLS.

Stack: Vite + React + Tailwind · Supabase (Postgres, Auth, Edge Functions, Secrets) · AI/ML API → anthropic/claude-opus-5 for the reasoning path, anthropic/claude-sonnet-5 for enrichment.

10
Impact

20 minutes → under 30 seconds.

That is the time to assess one account's risk: from opening four tools, reading recent history and forming a judgement, to a single ranked view with a grounded explanation already written.

The 20-minute baseline is stated as an assumption, not a measurement. We are not claiming a churn-reduction percentage — we have not run the experiment that would justify one.

Reproducible

Deterministic scoring. Same signals, same number, every time.

Auditable

Every score shows its per-signal breakdown. Every decision lands on a timeline.

Safe by construction

Human approval required. No send path exists in the code.
